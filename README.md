# Craft Corner Label Maker

## About the Project
### Why this Exists

My mother operates The Craft Corner, a small local business which produces personalised labels for school supplies—such as name labels, iron-ons and bag tags—printing and cutting them to order. Each order received through her Shopify store had to be turned into artwork by hand: first read the order, then type the child's name and school into the appropriate template, arrange it on a sheet, check it over and finally send it to the plotter to cut. This method worked, but it wasn't scalable, and small errors—like a misspelt name, the wrong school being used, or a sheet being sent to print only partly filled—ended up wasting both time and materials.

I began to develop a small set of tools for her business in mid-2026—this one is the component which automates the order-to-sheet process end to end by retrieving the orders from Shopify, converting them into label records, arranging them, producing the labels, and then exporting the print-ready sheets, including review and undo features so that nothing is sent to the cutter without being checked. It has been handling the business's daily label production since then and is not merely a demonstration or a project done as part of a class.

### Honesty & Transparency

I created and developed each component of this project by myself—covering the architecture, the pipeline stages, the rendering and packing logic, and the entire structure—step by step, through a number of iterations, working on it all on my own for several months until it had become the fully automated system that it is now. As I was doing this, I gained a great deal of knowledge, including about Shopify's API and PyQt6, as well as font rendering and bin-packing algorithms.

I made use of AI (specifically Claude) as a tool when developing the project—mainly in order to speed up bug fixing and to allow me to work more efficiently in languages in which I had less experience, such as TypeScript/React and FastAPI. A minor portion of the Python code was assisted by AI, even though most of it was written by myself. Furthermore, I have been giving continuous support, carrying out testing, and addressing bugs right throughout the whole development process; it wasn't a project that was once generated by AI, but one that has been actively maintained and improved by me over time.

## Technical Structure
**Interfaces**

The project ships three ways to run the same underlying pipeline:

- The desktop application (main.py) is a GUI built using PyQt6 for everyday production use.
- A web application (app.py) consisting of a FastAPI server together with a React/TypeScript frontend, which opens directly in the browser.
- The CLI (cli.py) provides each pipeline stage individually so that it can be used for scripting, debugging, and dry runs.

**Order pipeline**

The main pipeline (orchestrator/pipeline.py) operates in five stages, each of which can be run on its own and can be resumed using --run-dir:

1. **Fetch**: Uses a dedicated REST client (`shopify/client.py`) to retrieve the orders from Shopify, with retry functionality, or imports them from a CSV file.
2. **Transform** takes the raw order line items and converts them into structured student/label records, identifying any problems (instead of simply dropping them) and printing a summary indicating whether each order is ready or blocked.
3. **Extract** – matches the items on the order to the product regions/SKUs by using a configurable SKU map.
4. **Pack** — uses a packing strategy to place the label tiles on the sheets, checking the fill-threshold before finalising a sheet.
5. **Export** — produces the final sheets, prepares a report, and (if desired) tags the processed orders back in Shopify.

The run-all command carries out each stage for use in normal production conditions, while --no-tag enables export in safe mode so that sheets and a report are produced without any interaction with Shopify tags, for the purpose of testing.

**Shopify integration**

- **Admin API Client**: Includes credential handling and is pinned to a specific API version (in `shopify/client.py`).
- **CSV Import**: Provides an alternative to retrieving data via the live API (in `shopify/csv_import.py`).
- **Order Normalisation**: Detects student names and scripts, including distinguishing between Arabic and Latin scripts (`shopify/normalise.py`).
- **SKU Matching**: Identifies unmatched SKUs before they can lead to export failures (`shopify/skus.py`).
- **Review workflow**: The `export-review` command produces an editable Excel file containing the parsed orders; then, the `import-review` command compares the modified file with the original and reapplies the changes, this serving as a manual quality assurance step before any printing takes place.
- **Untag/undo**: the untag command takes away the "in-progress" Shopify tag from the orders in a run, allowing the batch to be safely redone.

**Label rendering**

- **Template Rendering**: The template-driven rendering engine (`core/render_engine.py`) puts the student name, school, grade, and order number onto each product's background artwork.
- **Strict Mode**: Refuses to silently produce a blank or faulty export when a background image or required font is missing.
- **Font Resolution**: Bundled, machine-independent fonts (`assets/fonts/`) ensure the system does not depend on local fonts, keeping output consistent across computers.
- **Name Cutout Fonts**: Provides dedicated fonts for die-cut and vinyl name designs, with each design having its own themed decorative font (`core/name_fonts.py`).
- **Region system** (`regions/`): each artwork template is accompanied by a JSON sidecar file that specifies the position of each product's crop zone, including a fingerprint check to identify any outdated regions following artwork edits.
  The candidate regions can be automatically drafted from the background's alpha channel — but they must always be manually reviewed before being used.
- **Region Template Generation**: Creates a PNG file with a pixel grid for manually measuring and defining new regions.
- **Sheet Packing**: Packs and tiles sheets using `plotter/pack.py`, `plotter/tiles.py`, and `plotter/SpaceOptimizer.py`, with the aim of minimising wasted vinyl.
- **Iron-on Sheets**: Handles iron-on sheets separately from regular label sheets, with their own sheet sizes and fill thresholds.
- **Sheet Numbering**: Continues sheet numbering across multiple runs, with a command-line instruction to reset the counter (`plotter/sheetnum.py`).
- **Sheet Compositing**: Combines rendered tiles into print-ready sheets and allows output to be exported in TIFF format for professional printing (`plotter/composite.py`).
- **Theming System**: Associates product themes with backgrounds and fonts (`core/theme_map.py`, `core/theme_admin.py`, and `data/themes_list.json`).

**Reporting & operational safety**

- **Audit Reports**: Tracks each sheet produced in CSV and Excel format (`report/`), with a `rebuild-report` command that can regenerate the Excel file from the CSV log if it becomes corrupted.
- **Run Journal**: Records the orders that were tagged or exported in each run, allowing a clean undo operation using the `untag` function (`orchestrator/journal.py`).
- **Run Retention**: Removes old run directories after a configurable number of days (`orchestrator/retention.py`).
- **Diagnostics**: Checks the installation, including fonts, templates, Arabic support, and backgrounds, and reports whether everything is ready before the production run.
- **Template Checks**: The `list-templates` command reports the readiness of each template, identifying missing region sidecars, fingerprint mismatches, and orphaned sidecars.

**UI layers**

- **Desktop** (`ui/`): includes panels for production runs, settings for connecting to Shopify, sheet configuration, region editing, and the reconciliation of blocked orders.
- **Web** (`server/`, `web/`): this includes a FastAPI backend which provides the same pipeline via HTTP, together with a Vite/React frontend featuring tabs for production, history, templates, themes, and settings.

**Project structure**

```
main.py         Desktop application entry point
app.py          Web application entry point

core/           rendering engine, fonts, themes, templates, settings
plotter/        sheet packing, tiling, compositing, TIFF export
regions/        region sidecar model, validation, auto-proposal
shopify/        API client, CSV import, normalisation, review, SKU matching
orchestrator/   pipeline orchestration, run journal, retention
report/         CSV/Excel reporting, report viewer
server/         FastAPI backend for the web app
web/            React/TypeScript frontend (Vite)
ui/             PyQt6 desktop UI
tests/          test suite
assets/         fonts, background artwork, cut-zone and template definitions
data/           theme list, font config, pack composition
cli.py          command-line interface
```

**Requirements**

- The Python dependencies are listed in `requirements.txt` (specifically Pillow, FastAPI/uvicorn, the Shopify/report libraries, support for Arabic text shaping, and optionally the Selenium renderer, etc.)
- Frontend dependencies: check `web/package.json` for React 19, Vite, Tailwind, and TypeScript.

**Testing**

```
pytest
```

The suite of tests (in the tests/ directory) includes coverage of packing and tiling geometry, the Shopify client, region validation, report generation, and the pipeline architecture.

**Getting started**

1. Install Python packages from `requirements.txt`.
2. Run the command python -m cli doctor in order to verify that the fonts, templates, and Arabic support have been correctly set up.
3. Set up the Shopify credentials and the sheet settings.
4. First, run a full pipeline pass in safe mode.
   ```
   python -m cli run-all --no-tag
   ```
5. When you are satisfied, run it again without using the --no-tag option to tag the processed orders on Shopify.

Or you can start the desktop version (by entering `python main.py`) or the web version (by entering `python app.py`) to access the same pipeline via a graphical user interface.

> **Windows launcher:** If you (or the person using the system day-to-day) prefer to double-click rather than open a terminal, save a `.bat` file beside `main.py`/`app.py`, such as:
>
> ```bat
> @echo off
> cd /d "%~dp0"
> python app.py
> pause
> ```
>
> Just save it as `run.bat` (or something similar) and the application will start with a single click. If you prefer the desktop interface, replace `app.py` with `main.py`.
